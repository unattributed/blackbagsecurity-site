  <section class="market-section market-section--soft" aria-labelledby="aotp-why"><div class="wrap"><div class="market-section__head"><div><p class="market-kicker">Why it exists</p><h2 id="aotp-why">Agentic testing needs stronger controls than <span>ordinary automation.</span></h2></div><p>A script performs a known task. An agent can plan, adapt, select tools, and continue. That capability only becomes useful for professional security work when campaign authority, budgets, approvals, stop conditions, evidence quality, and human review are part of the execution architecture.</p></div>
    <div class="market-card-grid market-card-grid--3"><article class="market-card"><span class="market-card__code">Campaign authority</span><h3>Scope is an executable constraint.</h3><p>Targets, rules of engagement, budgets, approvals, and stop conditions are established before execution can proceed.</p></article><article class="market-card"><span class="market-card__code">Governed execution</span><h3>The model does not become authoritative state.</h3><p>Local models assist planning while deterministic Python state and controlled adapters govern what actually executes.</p></article><article class="market-card"><span class="market-card__code">Evidence before finding</span><h3>Interesting output is not automatically truth.</h3><p>Raw evidence, provenance, replay, negative controls, and human review allow unsupported candidates to be rejected.</p></article></div>
  </div></section>

  <section class="market-section market-section--grid" aria-labelledby="aotp-loop"><div class="wrap market-split"><div class="market-message"><p class="market-kicker">Control loop</p><h2 id="aotp-loop">Give AI room to assist <span>inside a bounded campaign.</span></h2><p>The agent can help choose the next useful objective or technique, but execution remains gated by authority and the campaign can be stopped, reviewed, replayed, and reconciled at any point.</p></div>
