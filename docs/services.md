      <div class="market-section__head">
        <div><p class="market-kicker">The service catalogue</p><h2 id="service-catalog-title">What Black Bag Security <span>actually does.</span></h2></div>
        <p>These are distinct technical engagements, not four names for the same penetration test.</p>
      </div>

      <div class="market-card-grid market-card-grid--2">
        <article class="market-card">
          <span class="market-card__code">01 / Application &amp; API Security</span>
          <h3>Find the paths that let application users do more than the design intended.</h3>
          <p><strong>Use it when:</strong> an application, API, customer portal, administrative interface, SSO flow, or business workflow needs adversarial testing.</p>
          <p><strong>We examine:</strong> authentication, MFA and recovery, session handling, object and function authorization, role boundaries, APIs, input handling, browser behavior, protected state changes, and business logic.</p>
          <p><strong>You receive:</strong> validated abuse paths, affected roles and objects, reproduction context, remediation direction, and retest results where included.</p>
          <a href="{{ '/services/application-api-security/' | relative_url }}">Application &amp; API Security →</a>
        </article>

        <article class="market-card">
          <span class="market-card__code">02 / Adversary Validation</span>
          <h3>Find out whether an attacker can reach the outcome your controls are supposed to prevent.</h3>
          <p><strong>Use it when:</strong> the concern spans identity, endpoints, infrastructure, cloud, trust relationships, monitoring, or multiple defensive layers.</p>
          <p><strong>We examine:</strong> objective-led attack paths, identity and privilege, control bypass, lateral opportunity, reachable assets, telemetry, detection coverage, and response assumptions that are explicitly in scope.</p>
          <p><strong>You receive:</strong> the attack path, control outcomes along that path, observed detection or visibility gaps, material blockers, and a defensible statement of what the attacker could and could not achieve.</p>
          <a href="{{ '/services/adversary-validation/' | relative_url }}">Adversary Validation →</a>
        </article>

        <article class="market-card">
          <span class="market-card__code">03 / AI Security</span>
          <h3>Test the whole AI trust system, not just the prompt box.</h3>
          <p><strong>Use it when:</strong> models can retrieve information, browse, call tools, retain memory, act as agents, consume untrusted content, or make decisions that affect users or systems.</p>
          <p><strong>We examine:</strong> prompt injection, source confusion, retrieval and memory boundaries, browser and DOM state, tool authorization, identity propagation, sensitive-data exposure, guardrails, and consequential actions.</p>
          <p><strong>You receive:</strong> tested trust boundaries, reproducible adversarial cases, affected data or tool paths, guardrail failures, and practical control changes tied to the observed behavior.</p>
          <a href="{{ '/services/ai-security/' | relative_url }}">AI Security →</a>
        </article>

        <article class="market-card">
          <span class="market-card__code">04 / Secure Systems Engineering</span>
          <h3>Build the security property into the architecture instead of adding it after deployment.</h3>
          <p><strong>Use it when:</strong> a sensitive service, platform, appliance, control plane, or operational system needs architecture, hardening, containment, or recovery engineering.</p>
          <p><strong>We engineer:</strong> privilege separation, least privilege, authentication and secrets, trust boundaries, service exposure, secure configuration, logging, validation, backup, rollback, recovery, and operator-safe procedures.</p>
          <p><strong>You receive:</strong> architecture and hardening decisions, implementation or configuration artifacts where in scope, validation procedures, and an operating or recovery path the team can actually use.</p>
          <a href="{{ '/services/secure-systems-engineering/' | relative_url }}">Secure Systems Engineering →</a>
        </article>
